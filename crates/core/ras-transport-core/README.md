# ras-transport-core

The HTTP transport behind the Rust clients that the Rust Agent Stack macros generate.

The clients generated by `rest_service!`, `jsonrpc_service!` and `file_service!`
do not call `reqwest` directly.
They build a `TransportRequest` and hand it to an `HttpTransport`,
so the same client can run over the network, in a browser,
or in-process against an Axum router in a test.
You add this crate as a dependency because the generated code names it;
you use it directly when you pick or write a transport.

## Transports

- `ReqwestTransport` (`reqwest` feature) sends requests over the network through a `reqwest::Client`.
  On native targets it streams request and response bodies.
- `AxumTestTransport` (`axum-test` feature, native only) wraps an `axum_test::TestServer`,
  so a test can drive a generated client against a router with no sockets.

Every generated client builder has `build_with_transport(...)`,
which takes an `Arc<dyn HttpTransport>`:

```rust,ignore
use std::sync::Arc;
use axum_test::TestServer;
use ras_transport_core::AxumTestTransport;

let server = TestServer::builder().mock_transport().build(app)?;
let client = UserServiceClient::builder("http://localhost")
    .build_with_transport(Arc::new(AxumTestTransport::new(server)))?;
```

To write your own transport, implement `HttpTransport::execute`.
A transport does not inspect the status code;
the generated client calls `TransportResponse::error_for_status` for that.

## Features

| Feature | Default | What it does |
| --- | --- | --- |
| `reqwest` | no | `ReqwestTransport`, on native and `wasm32` targets. |
| `fs` | no | Native streaming of file parts from disk: `MultipartBuilder::file_path` and `stream_part`. Pulls in `tokio` and `tokio-util`. |
| `axum-test` | no | `AxumTestTransport`. Native only. |

## Errors

Every client call returns `Result<_, TransportError>`.
The variants separate failures a caller usually handles differently:
`Connection`, `Timeout`, `Status { status, body }` for a non-2xx answer,
`Serialize`, `Deserialize`, `Body`, `InvalidHeader`,
and `JsonRpc { code, message, data }` for a JSON-RPC error object,
where `data` is the error's optional `data` value.

`TransportError` is `#[non_exhaustive]`.
A `match` on it needs a wildcard arm,
and a pattern on a variant with fields needs `..`.

## WASM

On `wasm32`, `HttpTransport` is not `Send`,
because the browser runtime is single-threaded.
The fetch API cannot stream a request body,
so `ReqwestTransport` collects a `RequestBody::Stream` before it sends it,
and it reads the whole response body before returning.
Per-request timeouts are not applied on `wasm32`.
`MultipartBuilder::file_path` and `stream_part` are native only.

The `WebSocketTransport` trait in `ras-jsonrpc-bidirectional-client`
follows the same pattern for WebSocket connections.

```toml
[dependencies]
ras-transport-core = { version = "0.2", features = ["reqwest"] }
```
