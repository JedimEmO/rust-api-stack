# ras-file-core

Runtime types for file services generated by `ras-file-macro`.

You implement the handler trait that `file_service!` generates,
and its methods take and return the types in this crate:

- `FileRequestContext` carries the request method, path, headers and the authenticated user, if any.
- `IncomingFile` is a streaming upload part with a byte limit; read it with `next_chunk()` or skip it with `drain()`.
- `UploadSummary` lists the accepted parts and their sizes when an upload finishes.
- `JsonResponse<T>` is the upload response body with its status and headers.
- `DownloadResponse` builds a download from bytes or a stream, with `content_type`, `content_length`, `attachment` and `etag` helpers.
- `FileError` and `FileResult<T>` are the error type and its result alias. Each error maps to an HTTP status and the message the client sees.
- `sanitize_filename` reduces an untrusted upload filename to one safe path component. The generated server already applies it to file parts.

The crate does not depend on Axum.
The generated server adapts HTTP requests into these types.

```toml
[dependencies]
ras-file-core = "0.2.1"
```

See the [`file_service!` guide](../../../documentation/src/macros/file-service.md)
for how the handler methods use these types.
