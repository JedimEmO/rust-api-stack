# ras-rest-core

Runtime types for REST services generated by `ras-rest-macro`.

Handlers of a `rest_service!` trait return `RestResult<T>`.
This crate defines that type, the response and error types behind it,
and re-exports what the generated server code refers to,
so the API crate needs fewer direct dependencies.

## Key types

- `RestResponse<T>` wraps a response body with an explicit HTTP status.
  `ok`, `created`, `accepted` and `no_content` cover the common ones.
- `RestResult<T>` is `Result<RestResponse<T>, RestError>`, the return type of every handler.
- `RestError` carries a status and the message the client sees.
  `RestError::with_internal` also attaches an internal error,
  which the generated server logs and never sends to the client.
- `RestResultExt` converts an ordinary `Result<T, E>` into a `RestResult<T>`,
  with status `500` or one you choose.

The crate also re-exports `VersionMigration` from `ras-version-core`,
which versioned endpoints implement,
and the auth types `AuthProvider`, `AuthenticatedUser`, `AuthError` and `AuthResult`
from `ras-auth-core`.

## Example

```rust
use ras_rest_core::{RestError, RestResponse, RestResult};

async fn get_user(id: u64) -> RestResult<String> {
    if id == 0 {
        return Err(RestError::bad_request("user id must be non-zero"));
    }

    Ok(RestResponse::ok(format!("user-{id}")))
}
```

A `RestError` reaches the client as JSON, `{ "error": "<message>" }`,
with the error's status code.

```toml
[dependencies]
ras-rest-core = "0.2.1"
```

See the [`rest_service!` guide](../../../documentation/src/macros/rest-service.md)
for how handlers, versioning and errors fit together.
