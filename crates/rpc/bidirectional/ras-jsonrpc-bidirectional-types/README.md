# ras-jsonrpc-bidirectional-types

The types shared by the bidirectional JSON-RPC server and client:
the WebSocket message format, connection identity, and the connection manager trait.

You meet these types when you implement a service generated by
[`jsonrpc_bidirectional_service!`](../ras-jsonrpc-bidirectional-macro),
whose handlers receive a `ConnectionId` and a `&dyn ConnectionManager`,
or when you write your own connection manager.
Applications otherwise use them through
[`ras-jsonrpc-bidirectional-server`](../ras-jsonrpc-bidirectional-server) and
[`ras-jsonrpc-bidirectional-client`](../ras-jsonrpc-bidirectional-client).

## Key types

| Type | What it is |
|---|---|
| `BidirectionalMessage` | Every message on the socket, in either direction. |
| `ServerNotification` | A notification from the server to one connection. |
| `BroadcastMessage` | A notification to every connection subscribed to a topic. |
| `ConnectionId` | A connection's identity, backed by a UUID. |
| `ConnectionInfo` | What the server knows about a connection: its user, subscriptions, metadata and connect time. |
| `ConnectionManager` | Trait for tracking connections and sending or broadcasting to them. |
| `MessageSender` | Trait for sending messages on one connection; `MessageSenderExt` adds helpers such as `send_notification`. |
| `BidirectionalError` | The error type of this crate; `Result<T>` is the matching alias. |

`ConnectionManagerExt`, in the `manager` module, adds `notify_connection`, `notify_topic`
and per-user helpers to every `ConnectionManager`.
`NoOpMessageSender` discards what it is sent, which suits tests.

## The message format

`BidirectionalMessage` is serialized as a JSON object with a `type` field in snake case.
A JSON-RPC request travels as `{"type": "request", "jsonrpc": "2.0", "method": ..., "params": ..., "id": ...}`,
and the other variants are `response`, `server_notification`, `broadcast`,
`subscribe`, `unsubscribe`, `connection_established`, `connection_closed`, `ping` and `pong`.
A client in another language needs to speak this format to talk to the server.

## Example

```rust
use ras_jsonrpc_bidirectional_types::{
    ConnectionId, ConnectionInfo, MessageSender, MessageSenderExt, NoOpMessageSender,
};
use serde_json::json;

let connection_id = ConnectionId::new();
let mut info = ConnectionInfo::new(connection_id);
info.subscribe("updates".to_string());
assert!(info.is_subscribed_to("updates"));

// Any MessageSender works here; NoOpMessageSender discards the messages.
let sender = NoOpMessageSender::with_connection_id(connection_id);
assert_eq!(sender.connection_id(), connection_id);
sender.send_notification("user.updated", json!({ "id": 123 })).await?;
```

## Platform support

The crate builds for `wasm32` as well as native targets.
`WebSocketMessageSender`, which writes to a `tokio-tungstenite` sink, is native only.
